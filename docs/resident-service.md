# Windows 本机常驻方案

2026-09-26：此前链接再次无法打开时，4173 端口无服务，Windows 上次开机时间为当天 09:31。旧版启动器只创建独立进程，不具备重启电脑后的自动启动能力。现以 Windows 自动任务和阅读器守护进程共同管理运行。

## 已实施

- 固定地址 `http://127.0.0.1:4173/`，继续监听本机回环地址。
- 按当前 Windows 用户注册 `LittleStoryGarden-<用户 SID>` 任务，登录时启动，每分钟补启动；运行中的实例不会重复启动。
- 任务使用当前用户的普通权限，无需保存 Windows 密码。后台窗口隐藏；允许在电池供电时运行，没有连续运行时长上限。
- 守护进程定期请求 `/api/health`；阅读进程退出时自动重启，连续无响应时重启自己管理的进程，失败按上限 30 秒退避。
- 守护进程与阅读进程保持进程间连接，守护退出后阅读进程也会结束，避免遗留占用端口的进程。
- 本机命名管道限制同一安装目录的守护进程只能存在一个。其它应用占用端口时报告冲突，不结束其它应用。
- `.runtime/reader-4173/` 提供状态与滚动日志，最多约 4 MB；打包时排除。
- 启动器可重复运行；提供查看状态、修复启动和停用常驻服务入口。停用不清除书架、素材、音频或学习记录。

## 故障验证

`tests/service-recovery.ps1` 对实际安装执行以下检查，只结束本项目经过路径核对的 Node 进程：

1. 检查 Windows 登录触发器、每分钟恢复、忽略重复实例、无限运行时间及电池设置。
2. 重复运行启动器，健康服务的 PID 保持不变。
3. 结束阅读进程，等待守护进程恢复新的健康实例。
4. 单独结束守护进程，确认旧阅读进程随之结束，没有遗留进程。
5. 等待 Windows 自行重新运行守护进程，并恢复阅读服务；测试期间不手动启动任务。
6. 访问原链接，确认 HTTP 200 和绘本首页。

实际结果与恢复耗时见 `tests/service-recovery-results.json`。还通过原课程 12 项浏览器流程回归；外部浏览器使用本机安装的 Edge、独立测试数据及正式 CSP 检查首页、真实图片、书架和制作新集入口。

没有为了验证而重启或注销用户电脑：登录自动启动依据已注册且导出核对的 Windows 任务配置确认；进程故障恢复经过真实结束进程测试。

## 使用范围

电脑需开机、处于当前用户登录状态且未休眠，登录或唤醒后等待服务就绪。关闭 Codex 或浏览器不影响 Windows 管理的常驻任务。其它电脑或手机不能使用本机 `127.0.0.1` 地址。

Codex、Edge、Chrome 均可访问这个本机网页；各浏览器保存的书架和进度互相独立，不自动同步。此修改未迁移或删除用户原有浏览器数据。

源码目录是任务的固定运行位置。移动或删除目录前，在原目录运行「停用常驻服务.cmd」；移动后再运行新目录的「启动阅读器.cmd」。
